照着下面 5 步操作。配置正确后，Sub-Panel 才能按真实订阅者 IP 进行云厂商、频率和多设备检测。

先记住这两个概念 真实访客 IP 是拉取订阅的用户；可信代理 IP 是连接 Sub-Panel 的 CDN 回源节点或本机 Nginx。两者不是同一个 IP。
1在 CDN 面板添加订阅域名让订阅请求先到 CDN，再回源 Sub-Panel
加速域名你的订阅域名例如 sub.example.com
回源地址Sub-Panel 服务器 IP不要填 V2Board 源站
回源端口18443默认订阅网关端口
回源协议HTTP外层 HTTPS 由 CDN 证书负责
回源 Host订阅域名或保持原 Host不要改成其他机场域名
缓存关闭 / 绕过订阅内容不可被 CDN 公共缓存
□ HTTPS 证书已生效　□ Query 参数和完整路径原样回源　□ 未开启页面缓存
2让 CDN 透传真实访客 IP在 CDN 的回源 Header / 请求头设置中完成
Header应填写的值说明
X-Real-IP访客真实 IP推荐，单值最直观
X-Forwarded-For保留 / 追加客户端 IP不要覆盖已有链路
CF-Connecting-IPCloudflare 自动提供仅 Cloudflare 使用
找不到这个设置？在 CDN 面板搜索“回源请求头”“客户端真实 IP”“X-Forwarded-For”或咨询厂商。不要手工填写某个固定访客 IP。
3配置 Sub-Panel 的可信代理选择你的部署方式，复制配置到 /opt/Sub-Panel/config.yml

            仍然识别失败？展开故障排查
            

              
Remote IP 不可信：把诊断里的 Remote IP 加入 trust_proxies；如果是动态 CDN 节点，应添加厂商公布的完整回源 IP 段。

              
Header 全部为空：CDN 没有透传真实 IP，回到第 2 步设置回源 Header。

              
Client IP 等于 CDN IP：Header 值可能填成了 CDN 节点 IP，检查变量是否选择了“客户端 IP / 访客 IP”。

              
经过 aaPanel/Nginx：Sub-Panel 的直接连接通常是 127.0.0.1，应信任本机代理，同时让 Nginx 保留 CDN 传来的 X-Forwarded-For。

              
最后检查：用手机流量刷新一次真实订阅，再到“请求日志”确认记录的 IP 是手机运营商 IP，而不是 CDN/AWS 节点 IP。
